## 1. 你要做什麼（Definition of Done）

做一個 Claude Code plugin 的**框架**：一條常駐在輸入框正上方的狀態帶，它由多個獨立「面板（panel）」組成，每個面板可以單獨開關，版面由框架統一調度。

這一輪**只交付框架 + 一個 hello-world 面板**。真正有用的面板（agent 控制台、git、觀測）規格寫在第 7 節，這次不實作。

完成的可觀察定義，四條**全部**要成立：

1. `claude plugin validate --strict <dir>` exit 0，且輸出的 `calls:` 那行**只有** `$.ui.resolve`、`$.ui.invalidate`、`$.clock.*`、`$.store.*`、`$.command.register`、`$.env.get`。（出現 `$.process.run`、`$.fs.write`、`$.http.fetch` 就是設計走偏了，見第 6 節。）
2. `claude plugin test <dir>` 全過，**連跑兩次**都 0 fail。
3. 開兩個面板、關掉其中一個，另一個**不重新載入**（畫面不閃回「載入中」）。
4. 終端寬度從 200 縮到 30，每一步的每一行文字**顯示寬度都不超過可用欄數**（中文算兩格），而且不換行、不溢出。

## 2. 為什麼是「一個 plugin 多個面板」而不是「多個 plugin」

〔實測〕**跨 plugin 搶同一個 render site 時，先載入的那個獨佔。** 兩個 plugin 都 hook `ui.render{component=AbovePrompt}`，先跑的直接 return 樹、不呼叫 `next(e)`，後面那個畫的東西**整個消失**。而且兩棵樹不能合併——把 `next(e)` 的結果當 child 塞…

```
hook failed: <plugin>: returned a drawing that holds an object that is not plain data
(a class instance) ... (ui.render; skipped; its last next() run's result stands)
```

最後那句是好消息：**hook 失敗時「上一次 next() 的結果留下」**，所以壞掉的面板不會讓整條帶變空白。

所以「一堆各自畫帶的 plugin」這條路不可行——使用者裝第二個之後第一個會消失，而且看不出原因。**同一個 plugin 內部沒有這個問題**：一個 `ui.render` hook，裡面自己把 N 個面板組…

代價（要寫進 README）：第三方不能貢獻面板，只能發 PR。對「一個 Console」來說這是…版面本來就需要有人統一調度。

## 3. ⛔ 動工前必須知道的事實

### 3.1 啟用與載入

- function hooks **預設是關的**。GrowthBook 旗標 `tengu_plugin_hooks_modules` 預設 false，`CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` 是 override。
- `disableAllHooks`、`allowManagedHooksOnly`、safe mode、`--bare` **任一成立則整層不載入**。
- 開發：`claude --plugin-dir <folder>`，該資料夾**會被 watch**，存檔就熱重載。
- 〔實測〕**放進 `~/.claude/skills/<name>/` 會自動載入**，識別為 `<name>@skills-dir`，不需要 marketplace。但 `--plugin-dir` 的同名 plugin **優先**，會讓 skills-dir 那份 `Not loaded`。
- 〔實測〕`claude plugin list` 顯示 `Status: ✔ loaded` **不代表 hooks module 跑了**——它只表示 manifest 被讀到。要確認 module 真的載入，看 `claude --debug-file <f>` 裡的 `hooks module <name> loaded (worker, environment N, tier user); events: ...`。
- 個別關閉：`claude plugin disable <name>@skills-dir`。**格式必須帶 `@skills-dir`**，只寫名字會 `not found in any editable settings scope`。

### 3.2 型別檔是唯一事實來源

在一個已啟用的 session 裡跑 `/plugin-types`，它從**正在跑的 build** 產出 `claude-code.d.ts`、`claude-code-plugins.d.ts`、`claude-code-mcp.d.ts`。**不要猜任何形狀，去讀它。** 版本更新就重新產生，不要手改。

三個型別檔沒說但會咬人的地方，〔實測〕：

- **含 JSX 的 hooks module 一定要 `.tsx`**。寫 `.ts` 的錯誤訊息是 `Expected ">" but found "flexDirection"`，完全不提副檔名。
- **`plugin.json` 必須放 `.claude-plugin/`**，放根目錄是 `No manifest found`。
- **`e.viewport.columns` 不是螢幕寬度**。終端 200 欄時它回 110（那是 transcript 欄寬）。**一律用 `e.props.bodyColumns`**。

### 3.3 render site 的硬限制

能常駐大面積的只有兩個：`Pane`（右側 dock）與 `AbovePrompt`（輸入框正上方橫帶）。**這個專案用 `AbovePrompt`**。

| 限制 | 數值〔實測〕 |
|---|---|
| Pane 在 **<144 欄安靜不畫**，且寬度**只在 `$.ui.open` 當下判定一次** | 130 欄啟動後拉到 180 等 8 秒仍無 |
| AbovePrompt | 沒有寬度門檻、不需要 `$.ui.open`，任何寬度都畫 |
| 重繪節流 | 一般 100ms；render hook 自己超過 34ms 會**靜默降級成 1 秒** |
| `maxRows` | 非全螢幕下**等於整個終端高度**（40 列終端給 14）。佔滿會把對話擠掉 |
| 引擎的收合記號 `[-]` | **蓋掉第一列最右 3 欄**。第一列的預算要額外扣 4 |
| 收合 | 由引擎處理（`ctrl+x ctrl+a` 或點 `[-]`）。**props 裡沒有 collapsed 欄位，plugin 看不到收合狀態** |
| 讓位 | `e.props.hasSurvey` 為 true 時**整條讓位**（`return next(e)`） |
| 終端真圖片 | **架構性不支援**（sixel 字串命中 0，渲染器主動清洗跳脫序列） |

高度預算建議：總高 9 列 = 標題 1 + 內容 N + 狀態 1 + 警示 1。**上限只能有一個來源**：寫 `const CHART_ROWS_MAX = BAND_ROWS_MAX - FIXED_ROWS`，不要另外寫一個數字。

### 3.4 Client：唯一有滑鼠與鍵盤的路

`Client` 是一個掛自己 `.tsx` 模組進去的元素，那個模組跑在**繪製執行緒**上，有自己的 state 與事件。它是唯一能拿到滑鼠座標的地方。代價寫在型別裡：**它的元素表沒有 `Raster`**。

- `hover` 在引擎裡**只是樣式**（「No hook runs and nothing crosses to the plugin」）。想要「滑鼠移過去顯示某個東西」，唯一的路是 `Client` + `surface.onPointer`。
- `surface.onPointer(fn)` 給 `{ type, x, y, button?, shift?, alt?, ctrl? }`，`type` 是 `down | move | up | enter | leave`，座標是相對 region 左上角的**字元格**。
- `surface.state` / `setState`、`surface.every`（frame clock）、`surface.onKey`（點擊取得焦點後）、`surface.post(data)` → plugin 的 `ui.message` hook。
- `ui.message` hook 回 `{ props }` 可以把新 props 交回那個實例。
- `module` 必須是**字面值路徑**（`module="./chart.tsx"`），變數會在載入時被拒。

**三個會咬人的地方**，〔實測〕：

1. **每次繪製都要重新掛 `onPointer`**。只掛一次的話回呼裡的 `props` **永遠是第一次那一份**。
2. **回呼裡要讀 `surface.state`，不能讀外層的閉包變數**（同一個原因）。
3. **元素數量不是問題**：70 根 × 4 列（280 個 `Text`）一次繪製量到 **1ms**。而 `ClientModule` 超時會被**直接卸載**。

**滑鼠追蹤**：〔實測〕Claude Code 啟用的是 `1003`（any-event），純移動事件送得到。**但那依終端模擬器與多工器而定**，所以 **click 是可靠路徑、hover 是加分**：所有功能都要在只有 click 的情況下可用。

### 3.5 那些會靜默失敗的地方（每一條都撞過）

| 現象 | 真正的原因 |
|---|---|
| `h is not a function`，指在「呼叫 h」那一行 | **JSX factory 就是 `h`**。自己宣告 `h` 會遮掉它 |
| 測試報 `no implementation for http.fetch` | **op 的 stub 必須回 `{ value: ... }` 或 `{ deny }`**。直接回物件會被引擎靜默跳過 |
| 引擎拒繪整棵樹：`props holds undefined (an array hole, a missing value)` | 傳給元素的 props 含 undefined。常見來源是兩處用了不同的欄位名 |
| 版面整排偏一欄，最右邊的標籤被吃掉 | 用了 `.length` 而不是顯示寬度。**中文佔兩欄** |
| 軸上的刻度全部消失 | 日期/時間格式解析不出來就 `continue`。要畫**看得見的記號**（`??:??`），不要靜默略過 |
| 一個面板的開關切換之後，其他面板全部閃回「載入中」 | **改 `userConfig` 會重載整個 module**，閉包變數全部重置。資料要放 `$.store` |
| 時間戳指向未來（`dataAt > at`） | 某個來源的時間戳是「區間結束」而另一個是「區間開始」…（畫、hover 命中）必須用同一個定義 |

### 3.6 `$.store`：跨 session 的狀態

- `get(key)` / `set(key, value)` / `delete(key)` / `keys()`，值是 JSON，全部加起來有上限。
- `get` 讀回來的是 `JSON.parse(JSON.stringify(value))`：Date 變 ISO 字串、`undefined` 欄位消失、Map/Set 變 `{}`。
- 〔查證〕實體位置是 `<pluginCacheDir>/store/<name>.json`，pluginCacheDir 預設 `~/.claude/plugins`；命名空間鍵是 plugin 的 provenance（`<name>@<marketplace>` 或 `<name>@inline`）。
- **沒有原子操作**。多 session 同時跑會有競態。接受偶發的重複抓取，但要讓重複抓取無害。

## 4. 架構

```
telltale/
  .claude-plugin/plugin.json
  hooks/
    hooks.json           ← { "modules": ["register.tsx"] }
    register.tsx         ← hooks module：資料、版面調度、面板註冊表
    band.tsx             ← Client surface module：畫 + 滑鼠
    panels/hello.ts      ← 示範面板（純函式）
    register.test.tsx    ← 測試
  README.md
  LICENSE
```

### 4.1 面板的形狀

面板是**純資料 + 純函式**，不碰 `$`、不碰 surface：

```ts
export type PanelLine = { text: string; tone?: "up" | "down" | "flat" | "dim" };
export type PanelView = { id: string; lines: PanelLine[]; minRows: number };
export type Panel = {
  id: string; label: string; defaultOn: boolean; minRows: number;
  poll?: (io: PanelIo) => Promise<unknown>; everyMs?: number;
  view: (data: unknown, columns: number, rows: number) => PanelView | null;
};
export type PanelIo = {
  now: () => Promise<number>;
  fetch?: (url: string) => Promise<{ ok: boolean; status: number; text: string }>;
};
```

**為什麼面板拿不到 `$`**：`validate` 的 `calls:` 那行是使用者評估這個 plugin 的唯一依據。把能力收在框架手上，宣告才有意義。

### 4.2 版面調度

```ts
export type Slot = { id: string; rows: number };
// 1. 固定列（標題、狀態）永遠留著
// 2. 剩下的列按面板順序分配，分不到 minRows 的面板整個不畫
// 3. 總高不超過 min(maxRows, BAND_ROWS_MAX)
export const layout = (
  panels: readonly { id: string; minRows: number; wantRows: number }[],
  maxRows: number,
): { slots: Slot[]; dropped: string[]; total: number };
```

**砍面板時要講出來**：`dropped` 要顯示在狀態列（例如 `⋯ git, trace 因高度不足未顯示`）。

### 4.3 開關

`plugin.json` 的 `userConfig` 每個面板一個 boolean 欄位（`"panel.hello": { "kind": "boolean", "label": "Hello panel", "default": true }`）。〔查證〕每個非 secret 的 `userConfig` 欄位**自動變成 `/config` 選單的一列**，改動會**重載 module 並帶新的 `options`**。**所以不要自己做開關 UI。** 但要處理重載：面板資料一律先寫 `$.store`，module 起來時**先讀快取畫出來**，再背景更新。

另外註冊 `/telltale`（`argumentHint: "[panel-id|on|off|status]"`），`command.run` hook 用 matcher 限定 `{ command: "telltale" }`。

## 5. 驗證方法（不可省，這是交付的一部分）

### 5.1 `claude plugin test` 能做什麼

離線把 `ui.render` 打進 hook 鏈、拿回**元素樹的 JSON** 做斷言。走樹找 `type === "Client"`。三件事：op 的 stub 回 `{ value }`；`session.start` 裡呼叫的每個 op 都要 stub，漏一個整個 hook 被跳過；**`Client` 內部畫的東西測不到**——能抽成純函式的全部抽出來直接測，元件只驗 props，剩下手動實測並註明「沒有自動測試守著」。

### 5.2 突變測試（這是最重要的一條）

對每一條「這個行為很重要」的程式碼，故意改壞一行，跑測試。轉紅 = 有人守。全綠 = 那條承諾沒有機制。基準要連跑兩次都 0 fail。全綠的那幾條要嘛補測試、要嘛在程式碼裡**明寫「這一條沒有被檢查」**。全綠時先問「它量的是什麼」（可能是同一個量宣告了兩次）。

### 5.3 手動實測

```bash
tmux new-session -d -s tt -x 150 -y 34 -c "$PWD" \
  "CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir $PWD --debug-file /tmp/tt.log"
sleep 15
tmux capture-pane -t tt -p | tail -14
grep -iE "does not validate|hook failed|refused" /tmp/tt.log
```

**那個 grep 不能省**。送滑鼠事件（SGR）：移動 `printf '\033[<35;%d;%dM' COL ROW`；左鍵按下 `'\033[<0;%d;%dM'`、放開 `'\033[<0;%d;%dm'`。這個測法繞過終端那一層。

## 6. 安全：這個專案的自我約束

〔實測〕`tool.call` hook 不呼叫 `next(e)` 就繞過 PreToolUse；`$.process.run` 不產生 classic 事件；`$.fs.*` 不受 `permissions.deny` 管。唯一的真閘是**載入前的靜態掃描**，粒度只到 `noun.method`。

規矩：1. **絕不宣告 `$.process.run`**（要本機能力就做本機小服務 + `$.http.fetch`）。2. **絕不 hook `tool.call` 或 `classic.*`**。3. **README 直接貼 `claude plugin validate` 的輸出。**

## 7. 之後要做的面板（規格已定，這一輪不實作）

### 7.1 agent 控制台
顯示所有 subagent 的 id / type / status / model，1 秒內反映；function hooks 關掉時仍能顯示（降級）。資料層走 PostToolUse shell hook 寫 JSONL，呈現層才用 function hooks。**樹狀縮排，不做橫向時間軸。** 聚合：同父同 type 同 status 的葉節點合併成 `TYPE ×N (…)`；超出預算時 MAIN 永遠展開 > 執行中 > 已結束。穩定排序：status 相同時用 agent id。狀態歷史鏈由 plugin 自己在 status 改變時 append。

### 7.2 git 面板
branch / ahead / behind / 未提交檔數 / 是否 worktree。**最該第二個做。**

### 7.3 觀測面板
讀 `<專案>/.claude-trace/events.jsonl`：過去 N 分鐘的工具呼叫次數、deny 次數、錯誤率。

### 7.4 顏色與視覺層級
顏色只表達嚴重度（綠/黃/紅）；不用空白列分組，用 `─── AGENTS ───`；沒有補間動畫，不閃爍。

## 9. 工作順序建議

1. 骨架 + `plugin.json` + `hooks.json`，讓 `validate --strict` 過。
2. 最小的 `AbovePrompt` hook 畫一行固定字，**先用 tmux 實測看到它**。
3. `layout()` 純函式 + 測試 + 突變。**先做調度再做面板。**
4. hello 面板 + `userConfig` 開關 + 重載後從 `$.store` 復原。
5. `Client` 版本 + click（hover 選配）。
6. `/telltale` command。
7. README（含 `validate` 輸出）、LICENSE、GitHub Actions。

**每一步都要連跑兩次測試**，每寫完一批測試就跑突變。
