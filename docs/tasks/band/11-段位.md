## 介面缺口先講清楚

`Panel<D>` 型別（`hooks/panel.ts`）要多一個 `stages?: Stages` 欄位（SDD §1.1a）才能讓 agents 面板（票 13）宣告 `stages`。**`panel.ts` 不在本票可碰清單**，本票不動它。`register.tsx` 讀 `p.stages` 一律用型別斷言 `(p as { stages?: Stages }).stages`，並在該行留註解「等 `panel.ts` 補上正式欄位（票 13 或後續）後拿掉斷言」。本票的驗收測試用一個手造的假面板物件（`as unknown as Panel`）注入 `stages`，不依賴 `panel.ts` 改動。

## 題目

### `layout.ts` 新增

```ts
export type Stage = "summary" | "compact" | "full";
export type Stages = { summary: 0; compact: number; full: "rest" }; // 面板宣告用的形狀（SDD §1.1a）；數值本身不影響下面的映射
export const STAGE_ORDER: readonly Stage[] = ["summary", "compact", "full"];
export const nextStage = (stage: Stage): Stage =>
  STAGE_ORDER[(STAGE_ORDER.indexOf(stage) + 1) % STAGE_ORDER.length]!;
export const rowsForStage = (stage: Stage): { minRows: number; wantRows: number } => {
  switch (stage) {
    case "summary": return { minRows: 0, wantRows: 0 };
    case "compact": return { minRows: 2, wantRows: 3 };
    case "full": return { minRows: 3, wantRows: CONTENT_ROWS_MAX };
  }
};
```

`rowsForStage` 的三組數字是 SDD §1.2 規則 8 的字面值（**不是**從面板宣告的 `Stages` 物件讀出來的——宣告只是「這個面板支援分段」的標記，映射對所有面板一致）。「沒有 `stages` 的面板照第一輪」＝ `register.tsx` 在 `p.stages` 不存在時，`wants` 仍用 `p.minRows`／`p.wantRows`（既有邏輯不變）。

### `hit.ts` 新增

`BandPanel` 加一個欄位 `stages?: boolean`（有沒有段位能力；可選，舊 fixture 不用改就仍合法）：

```ts
export type BandPanel = {
  id: string; label: string; rows: number; lines: PanelLine[];
  at: number | null; error: string | null;
  stages?: boolean; // NEW
};

export const titleClickKind = (id: string, props: BandProps): "stage" | "toggle" =>
  props.panels.find((p) => p.id === id)?.stages ? "stage" : "toggle";
```

（`hitPanel` 本身不變——它只回哪個 id 被點到；`titleClickKind` 是點到之後再問「這一下該送哪種訊息」。真正把兩者接起來、`$.ui.open`／post 訊息是票 16 `band.tsx` 的事，這裡只給純函式。）

### `register.tsx` 修改

- `ui.render{AbovePrompt}` 組 `wants` 時，每個面板先看 `(p as { stages?: Stages }).stages` 是否存在：有→從 `$.store.get(\`size.${p.id}\`)` 讀目前段位（缺省 `"compact"`），用 `rowsForStage(stage)` 算 `minRows`／`wantRows`；沒有→照舊用 `p.minRows`／`p.wantRows`。
- 組 `bandPanels` 時，每個 slot 的 `stages` 欄位＝`Boolean((p as { stages?: Stages }).stages)`。
- `ui.message` 的 data 判別式加 `{ kind: "stage"; id: string }` 分支：`id` 在面板表裡才處理；讀 `size.<id>`（缺省 `"compact"`）、算 `nextStage`、`$.store.set(\`size.${id}\`, next)`、`$.ui.invalidate("ui.render")`。**沒有 `stages` 的面板收到 `kind:"stage"` 一律忽略**（不是它的訊息）。

### `command.ts` 修改

`TelltaleState` 加：
```ts
export type TelltaleState = {
  order: { id: string; label: string; stages?: boolean }[]; // NEW: stages?
  panels: Record<string, boolean>;
  sizes: Record<string, Stage>; // NEW
  layout: { slots: { id: string; rows: number }[]; dropped: string[]; total: number };
  available: number;
};
export type TelltaleResult = { text: string; panels: Record<string, boolean>; sizes: Record<string, Stage> }; // sizes NEW
```

`runTelltale` 新增兩個分支（`RESERVED` 不需要改，`size` 不是保留字，因為它永遠緊跟在一個已知 panel id 後面才有意義）：

- 兩個 token、第二個是 `"size"`：該面板沒有 `stages` → `usage(state)`；有 → 回報目前段位，`text: \`${id}: size ${sizes[id] ?? "compact"}\``，`sizes` 不變。
- 三個 token、第二個是 `"size"`、第三個 `∈ STAGE_ORDER`：該面板沒有 `stages` → `usage(state)`；有 → 算 `from = sizes[id] ?? "compact"`、`to = 第三個 token`；相同 → `\`${id}: size ${from} (unchanged)\``（`sizes` 不變）；不同 → `\`${id}: size ${from} → ${to}\``，`sizes = { ...state.sizes, [id]: to }`。
- 三個 token、第二個是 `"size"`、第三個不是合法段位名 → `usage(state)`。
- 未知 id（`t0` 不在 `known`）一律先 `unknownPanel(t0, state)`，跟第一輪同順序判斷（先查 id 認不認得，再看子指令合不合法）。

`register.tsx` 的 `command.run` 處理器要把 `state.sizes` 從 `await $.store.get` 批次讀進來（每個有 `stages` 的面板一個 key），並在 `result.sizes !== state.sizes` 時把差異寫回對應的 `size.<id>` 鍵（跟現有 `result.panels !== state.panels` 判斷 diff 再寫的模式一致）。

### 驗收要覆蓋（照 SDD 這幾條字面）

1. `layout` 測試：`rowsForStage("summary")` = `(0,0)`、`("compact")` = `(2,3)`、`("full")` = `(3, CONTENT_ROWS_MAX)`；`full` 仍受既有 `layout()` 的 I2（`budget`／`BAND_ROWS_MAX` 上限）約束（用 `layout()` 整合一測，不只測 `rowsForStage` 單獨輸出）。
2. `hit` 測試：`titleClickKind` 對有 `stages: true` 的面板回 `"stage"`，沒有（`undefined`／`false`）回 `"toggle"`。
3. **循環順序一測**：`nextStage("summary")→"compact"→"full"→"summary"`，四次呼叫串起來驗證回到起點。
4. **同一個鍵一測**：用 `harness.ts` 的 `fakeEngine` + `makeRegister([stagedPanel])`，先 `fire("ui.message", {data:{kind:"stage", id}})` 兩次，記下 `store["size.<id>"]`；重來一次改用 `fire("command.run", {command:"telltale", args:"<id> size full"})`；斷言兩條路徑寫的都是同一個 store 鍵 `size.<id>`（不是各自维护一份影子狀態）。
5. hello／clock（無 `stages`）點標題仍是 `toggle`（相容既有 `hit.test.ts` 的假設，不需要新測試，但本票不能改壞它——`make check` 跑既有 `hit.test.ts` 會抓到）。
