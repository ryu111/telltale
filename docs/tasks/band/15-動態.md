## 題目

在 `hooks/cells.ts` 新增以下純函式，並把票 14 `renderCell` 裡「定形」（假裝沒有光點／打字機／呼吸、鏡頭硬跳）的暫代邏輯，換成真的用這些函式算出來的動態版本。`renderCell` 的簽名不變（`(cell, style, w, h, now, frame, cam)`），只有內部實作變。

### `curIx(cell: Cell, now: number): number`

```
inTransit = cell.status === "running" && cell.steps.length > 1 && (now - cell.steps[last].t0) < TRANSIT_MS
curIx = inTransit ? steps.length - 2 : steps.length - 1
```

`steps.length === 0` 是呼叫端的錯（`Cell.steps` 至少有 `prompt`），不用特別處理，測試不覆蓋這個輸入。

### `packetAt(cell: Cell, edgeLen: number, now: number): number | null`

只在**最後一條邊**（`curIx` 到 `curIx+1`，也就是最新節點正在抵達那條）回傳位置，其餘一律 `null`（沒有第二個光點）：

```
if (cell.status !== "running" || cell.steps.length < 2) return null;
const last = cell.steps[cell.steps.length - 1];
const age = now - last.t0;
if (age >= TRANSIT_MS) return null; // 已抵達，光點消失，節點常駐
return Math.min(edgeLen - 1, Math.floor((age / TRANSIT_MS) * edgeLen));
```

### `cameraTarget(stripW: number, w: number): number`

橫向（v1／v4）鏡頭目標：`Math.max(0, stripW - w + CAMERA_MARGIN)`（`CAMERA_MARGIN = 28` = 兩個節點寬＋一段連線，DESIGN §1）。

### `easeCamera(cur: number, target: number): number`

`Math.abs(target - cur) < 1 ? target : cur + (target - cur) * CAMERA_GAIN`。**回傳值不四捨五入**（呼叫端在真的拿去切字元位置時才 `Math.round`，這樣連續呼叫才會累積出平滑移動；每幀都 round 會卡在整數台階上，動畫看起來會跳格）。v2 縱向**不用這個函式**——硬鎖：`offset = Math.max(0, rows.length - body)`，直接指定,不經過 `easeCamera`（DESIGN §1「縱向硬鎖」）。

### `typewriterProgress(t0: number, now: number): number`

回傳 `[0, 1]` 的展開進度，從節點**抵達**（不是誕生）那一刻算起：`age = Math.max(0, now - t0 - TRANSIT_MS)`；`age >= BIRTH_MS ? 1 : age / BIRTH_MS`。打字機（節點名字顯示前 `Math.ceil(name.length * progress)` 個字元）與框展開（框寬 `Math.max(3, Math.ceil(NODE_W * progress))`，抵達前固定 3 欄）共用這個進度值，不要各自重算一次年齡。

### `isBreathing(now: number): boolean`

`Math.floor(now / BREATHE_MS) % 2 === 0`。只用在目前節點（`curIx` 那個）的框線粗細切換。

### `isFlashing(cell: Cell, now: number): boolean`

`now - cell.updatedAt < FLASH_MS`。用在 cell 邊框「剛有事件的 1 s 內亮綠粗體」。

### `slideOffset(bornAt: number, now: number): number`

新 cell 從右緣滑入用的左側留白欄數：`Math.max(0, Math.round((1 - Math.min(1, (now - bornAt) / SLIDE_MS)) * (NODE_W + 2)))`。`(NODE_W + 2)` 是滑入的最大位移（跟 `docs/設計/試衣間.html` 的 `slideIn` 一致，用既有常數推出來，不寫死 `14`）。v2 從下緣滑入沿用同一個函式回傳的欄數概念，只是套在列位移而非欄位移上（實作可以共用同一個數值，呼叫端決定用在 x 還是 y）。

### `renderCell` 的整合（把票 14 的暫代邏輯換掉）

- v1／v4 的鏡頭：`cam.offset` 每次呼叫用 `easeCamera(cam.offset, cameraTarget(stripW, availableWidth))` 更新，回傳的 `{ cam }` 帶新值；渲染時用 `Math.round(cam.offset)` 決定視窗起點。
- v2 的鏡頭：不維護 `cam.offset`（或維護但不 easing），直接用硬鎖公式；輸出的 `cam` 原樣傳回（或設成硬鎖值，供呼叫端一致性檢查，兩種做法都可以，測試不鎖這個）。
- 目前節點（`curIx` 那個）：`status==="running"` 時符號用 `current`／`currentFailed`（cell 失敗時）；框線粗細依 `isBreathing(now)` 切換（真=粗、假=細，對應 DESIGN 的呼吸節奏，粗細本身無法用字元表示時至少要讓測試能分辨兩種狀態——用不同的 tone 或不同的符號都算數，實作註解寫清楚選了哪種）。
- 抵達中的節點（`age(steps[last].t0) < TRANSIT_MS`）：名字用 `typewriterProgress` 裁切、框寬用同一個進度值展開；**該邊**（`curIx`→`curIx+1`）用 `packetAt` 畫光點（`SYMBOLS.packet`），光點前後各一格用 `SYMBOLS.packetTail`。
- 抵達後：前一個節點（原本的 `curIx`）名字必為 `greyDim`（DESIGN §2「已走過的節點：名字灰」），符號保留種類色（見票 14 的「符號保留種類色」段落，僅在 `running` 時生效）。

## Property 測試（I18；固定 seed，不裝 fast-check）

隨機產生一個 `status: "running"` 的 cell（2–10 個 step，每個 `t0` 遞增、最後一個 step 沒有 `t1`），再隨機取一批 `now`（涵蓋抵達前／抵達中／抵達後三段）。斷言：

1. **同一時刻只有一條邊可能有光點，且只能是最後一條**：對每個 `now`，只檢查 `packetAt(cell, edgeLen, now)`（本來就只代表最後一條邊）非 `null` 時，`curIx(cell, now) === cell.steps.length - 2`（換句話說，有光點的前提就是「正在抵達最後一個節點」，不會有第二種情況讓它非 `null`）。
2. **同一個 `TRANSIT_MS` 窗內取兩個不同的 `now`，光點位置不同**（真的在動）：在同一個抵達事件的 `[t0, t0+TRANSIT_MS)` 區間內，任取兩個相差 `> 0` 且都 `< TRANSIT_MS` 的偏移量餵給 `packetAt`，只要 `edgeLen` 夠大（例如 `EDGE_W`），兩次結果不應該恆等於同一個值（至少取樣兩次、涵蓋區間頭尾，兩點必不同——因為 `Math.floor(age/TRANSIT_MS*edgeLen)` 在整個區間單調遞增）。
3. **抵達後前一節點名字必為灰**：`now >= t0 + TRANSIT_MS` 時（該節點已抵達），用 `renderCell(...,"v1",...)` 找到前一個節點的 span，tone 必為 `greyDim`（`running` cell 的情況；本測試固定用 running cell）。
