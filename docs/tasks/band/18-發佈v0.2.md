## 題目

`plugins/telltale/README.md` 在既有結構上補：

- **`## What this plugin can touch` 區塊逐字更新**：跑一次 `claude plugin validate --strict --json plugins/telltale`，把 `hooks:`／`calls:` 兩行貼進去（v0.2 的九～十個 hook、十一個 `$` op，實際數字以跑出來的為準，不要用 SDD 文字裡的數字手抄——那是設計時的預期，實作完成後的真值以 validate 輸出為準，兩者不一致要回報，不要為了讓測試過而改 SDD）。
- **agents 面板一段**：什麼是 cell（main／subagent／背景任務三種來源）、三種樣式 `v1`／`v2`／`v4`、預設貼哪邊（引擎只給 `Pane` 右側 dock 與輸入框上方兩個位置，不是 SDD 草稿設計的四邊）。
- **`TELLTALE_DEV`**：`hello`／`clock` 兩個面板只在 `TELLTALE_DEV=1` 時註冊，一般使用者裝了只看到 `agents`；給一行環境變數設法範例。
- **背景任務 description 配對的限制**：同名並行的背景任務可能被錯誤的通知關掉（SDD §2.6 已知限制原文）；`Agent` 工具的 model 配對在同描述同時派兩個時可能配錯。
- **孤兒規則**：背景任務 30 分鐘無通知變「久跑」（經過時間變黃，仍是 running）、2 小時變「孤兒」（`?`，留到點掉或 `/telltale agents clear`）。
- **引擎只給兩個位置**：不是設計稿裡的四邊；README 要講清楚差異是引擎版本限制，不是產品決定放棄。
- **`/telltale agents style|edge|size|clear` 用法表**（照 SDD §1.6 v0.2 追加表逐列抄，含 `edge top/left` 的 `not available in this build` 那行）。
- **純即時顯示、無歷史回放**；**subagent 內部細節不保證**（引用票 16 `docs/實測/agents.md` 的實測結論：拿到了就寫「拿到」，退化了就寫「退化，只有三節點」——**這句話的措辭以票 16 實測結果為準，不要兩種都寫成「可能」**）。
- **`$.ui.open` 為什麼在 `calls:` 裡**：一句話解釋（Pane 需要 `open` 才會畫，`$.ui.*` 只負責畫東西，不是資料外流）。
