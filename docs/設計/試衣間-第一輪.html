telltale v0.2 · agents 面板

六種呈現，同一段假資料，真的在動

下面每個黑框是一條 telltale 帶子（最多 9 列）。同一套模擬的 session 同時餵給六種呈現——前三種（流程圖、狀態流、軌道）agent 本身會動，後三種是原本的 A／B／C：subagent 起停、背景 shell、主迴圈階段切換都是照 SDD §2.6 的規則跑的。切視圖、切段位、拉寬度、按事件按鈕看它們怎麼反應，然後在下面選一個。

G · trace 瀑布（照你給的參考圖）

整輪是最上面的 trace，每個 agent／背景任務是它底下的 span；左緣是這輪開始、右緣是現在，span 的長度是真的時間。running 的 span 用會流動的斜紋填，done 的變實心，failed 變紅。跟 Jaeger／參考圖同一套語言。


  


  

    

      
H · cell 圖（照 terminal-poster 那兩支影片）
一個任務一個方框 cell，main 在最左；cell 之間的連線有 ◆ 光點流動；running 的 cell 邊框上有一顆點繞著跑（每個 job 自己的 loop）；cell 多到超出寬度時「鏡頭」平滑跟到最近有變化的那格。

      
    

    

  


  

    

      
D · 流程圖
main 是左邊的節點，每個 agent 是右邊一個節點，中間是連線；running 的連線上有光點在跑，done 的連線變暗，failed 的變成虛線紅。

      
    

    

  


  

    

      
E · 狀態流
三欄狀態機 spawned → running → done／failed，agent 是晶片，狀態一變就從一欄滑到下一欄（約 0.6 秒），滑動本身就是「發生了什麼」。

      
    

    

  


  

    

      
F · 軌道
每個 agent 是軌道上一個會跑的標記，running 的一直往右跑（速度＝活動量），done 停在終點打 ✓，failed 停在原地打 ✗。一眼看「誰還在動」。

      
    

    

  


  

    

      
A · 極簡單色（備選）
綠／紅／暗／一般四階＋粗體。bar 只表達「活著多久」。

      
    

    

  


  

    

      
B · btop 式明度＋活動量
label 依 agent 類型分明度，bar 用 ▁▃▅▇ 表示每 6 秒的工具呼叫量。

      
    

    

  


  

    

      
C · k9s 式高密度表格
固定欄位、有欄名、running 列淡綠底。沒有時間軸，lanes／tree 切換對它無效。

      
    

    

  


  


  

    
三個一樣的地方spinner 80 ms 一幀、經過時間每秒跳、狀態切換那列粗體 1 秒、completed 60 秒後消失、failed 留到點掉（這裡按「結束一個」會先收最舊的失敗列）。

    
A 與 B 的差別B 多一條資料：每條 lane 的工具呼叫數時間序列。subagent 的呼叫數在 2.1.267 拿不到（只有主迴圈的 turn.step），這裡是模擬的；真做的話 subagent 的 bar 會退回 A 的樣子。

    
C 的取捨一列塞最多資訊、不需要 lanes／tree 兩套排版，票 14／15 合成一張；代價是沒有時間感。
